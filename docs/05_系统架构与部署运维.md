# 系统架构与部署运维

本文档定义 v1.0 成品的系统架构、运行方式、部署方式和维护规则。

## 1. 架构原则

v1.0 采用 local-first dashboard 架构：

```text
Official Open Data Sources
  -> Data Fetchers
  -> Raw Cache
  -> Processing Pipeline
  -> Processed Parquet / DuckDB Query Layer
  -> Streamlit Dashboard
  -> AI Summary / Report Export
```

核心判断：

- 数据量约 5 万级，Parquet + DuckDB 足够。
- dashboard 以研究和分析为主，不需要一开始上数据库服务。
- 数据 pipeline 和 UI 必须解耦。
- 无网络时仍能使用缓存数据。

## 2. 运行模式

### 2.1 本地研究模式

适用：

- 个人电脑。
- 研究工作站。
- 学生或研究助理本地运行。

命令：

```bash
python -m src.pipeline.build_all --use-cache
streamlit run app.py
```

### 2.2 首次初始化模式

适用：

- 第一次安装。
- 需要重新拉官方数据。

命令：

```bash
python -m src.pipeline.build_all --force
python -m src.pipeline.validate_outputs
streamlit run app.py
```

### 2.3 离线演示模式

适用：

- 无网络演示。
- 课堂或答辩现场。

要求：

- 使用 `data/processed/` 中已有 Parquet。
- 使用 `data/cache/source_manifest.json`。
- 不强制调用 LLM。
- 自动切换模板摘要。

命令：

```bash
streamlit run app.py
```

### 2.4 轻量部署模式

适用：

- 实验室内网。
- Streamlit server。
- 单用户或少量用户访问。

建议：

- 数据更新由命令行定期执行。
- dashboard 只读 processed 数据。
- 不在页面请求中实时下载官方数据。

## 3. 数据层

### 3.1 Raw 层

路径：

```text
data/raw/
```

用途：

- 保存官方下载 zip。
- 保存解压 CSV。
- 保存原始 MBIS CSV。
- 保存 district boundary JSON。

规则：

- 不手工改。
- 不作为 dashboard 直接读取源。
- 可以加入 `.gitignore`。

### 3.2 Processed 层

路径：

```text
data/processed/
```

必需文件：

```text
buildings.parquet
district_metrics.parquet
regulatory_notices.parquet
```

用途：

- dashboard 默认读取。
- 报告模块读取。
- 验证脚本读取。

### 3.3 Cache 层

路径：

```text
data/cache/
```

必需文件：

```text
source_manifest.json
pipeline_run.log
```

用途：

- 记录数据版本。
- 记录 pipeline 状态。
- 支持离线复现。

## 4. 应用层

### 4.1 Streamlit 页面

`app.py` 只负责：

- 设置页面配置。
- 初始化 session state。
- 加载 processed 数据。
- 调用各页面组件。
- 管理导航和筛选。

### 4.2 Dashboard 组件

建议结构：

```text
src/dashboard/
  navigation.py
  state.py
  data_intake.py
  portfolio_overview.py
  spatial_dashboard.py
  district_benchmark.py
  use_typology.py
  regulatory_signals.py
  ai_report_studio.py
  method_qa.py
  charts.py
  maps.py
  tables.py
```

## 5. AI 层

### 5.1 LLM 调用策略

LLM 调用只发生在用户点击生成摘要或报告时。

禁止：

- 页面加载时自动调用 LLM。
- 每次筛选自动调用 LLM。
- 发送全量建筑表。

### 5.2 Fallback

无 API Key 或 LLM 调用失败时：

- 使用模板摘要。
- 页面显示 fallback 状态。
- 报告记录摘要生成方式。

## 6. 报告层

报告生成模块读取：

- 当前筛选条件。
- 聚合指标 JSON。
- 数据版本。
- 模型版本。
- prompt 版本。
- AI 或模板摘要。

输出：

```text
outputs/reports/report_YYYYMMDD_HHMMSS.md
outputs/reports/report_YYYYMMDD_HHMMSS.html
```

## 7. 部署要求

### 7.1 本地部署

最低要求：

- Python 3.10+
- 4GB RAM 以上。
- 可访问网络用于首次下载官方数据。

安装：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m src.pipeline.build_all --force
streamlit run app.py
```

### 7.2 内网部署

建议：

- 固定一台机器定时更新数据。
- 用户只访问 Streamlit URL。
- processed 数据定期备份。
- API Key 放在服务器环境变量中。

### 7.3 云端部署暂缓

v1.0 不默认做公网云部署。原因：

- 官方数据更新和缓存需要明确策略。
- API Key 和报告输出涉及安全管理。
- 多用户并发和权限不是当前核心。

若进入 v2.0，可评估：

- FastAPI + React。
- Postgres / DuckDB server。
- 对象存储。
- 用户系统。
- 任务队列。

## 8. 运维规则

### 8.1 数据更新

建议频率：

- Building age records：每月或每季度检查一次。
- MBIS issued：每月更新。
- District boundary：低频更新，有需要再刷新。

更新命令：

```bash
python -m src.pipeline.build_all --force
python -m src.pipeline.validate_outputs
```

### 8.2 备份

建议备份：

- `data/cache/source_manifest.json`
- `data/processed/*.parquet`
- `outputs/reports/`

不强制备份：

- 可重新下载的 raw zip。
- 临时日志。

### 8.3 故障处理

| 问题 | 处理 |
| --- | --- |
| 官方下载失败 | 使用缓存数据，提示数据未更新 |
| 字段变化 | pipeline 停止并提示更新字段映射 |
| OP 日期解析率过低 | 阻止覆盖 processed 数据 |
| LLM 失败 | 使用模板摘要 |
| 地图渲染过慢 | 切换聚合或筛选后显示 |

## 9. 安全边界

v1.0 默认不处理敏感个人数据。

仍需注意：

- API Key 只放环境变量。
- 用户上传文件不自动外发给 LLM。
- 报告输出前提示用户检查内容。
- 不把全量原始数据发送给第三方模型。

## 10. 成品运行标准

v1.0 成品必须满足：

```bash
python -m src.pipeline.build_all --use-cache
python -m src.pipeline.validate_outputs
pytest
streamlit run app.py
```

以上全部可运行，才算具备稳定交付基础。
