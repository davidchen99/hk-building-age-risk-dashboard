# 技术执行规则

本文档用于约束后续批量 PR、自动化 agent 和人工开发。若本文档与早期需求描述存在细节冲突，以本文档和 `01_数据指标口径.md` 作为实现优先级更高的执行口径。

## 1. 执行原则

### 1.1 数据先行

所有 dashboard 功能必须建立在稳定的数据 pipeline 上。不能先写死前端示例数据，再回头补数据逻辑。

执行顺序：

```text
官方数据下载/缓存
  -> 字段标准化
  -> 数据质量校验
  -> 楼龄计算
  -> 风险评分
  -> 区域指标聚合
  -> dashboard 展示
  -> AI 摘要和报告
```

### 1.2 CLI 优先

每个核心数据处理步骤都必须可以通过命令行独立运行。dashboard 只调用已经生成或可缓存的数据，不把数据下载、清洗、评分全部塞进页面点击流程。

必须保留的命令入口：

```bash
python -m src.pipeline.build_all
python -m src.pipeline.validate_outputs
streamlit run app.py
```

### 1.3 可复现优先

每次生成分析结果，都必须能追溯：

- 使用了哪个数据源。
- 数据是什么时间下载的。
- 风险模型是什么版本。
- prompt 是什么版本。
- 处理后数据生成时间。

这些信息写入 `data/cache/source_manifest.json`，并进入导出报告。

### 1.4 页面逻辑必须薄

`app.py` 只负责：

- 页面导航。
- 调用组件。
- 读取处理后数据。
- 维护筛选状态。

禁止在 `app.py` 中写大量：

- 字段清洗逻辑。
- 风险评分逻辑。
- LLM prompt 拼接逻辑。
- 报告生成逻辑。
- 复杂空间匹配逻辑。

这些逻辑必须放在 `src/` 下对应模块。

## 2. 不可违反的规则

### 2.1 原始数据不可手改

`data/raw/` 下的数据只允许由下载脚本写入，不允许手工改 CSV 内容。任何修正都应写在 pipeline 中，并输出到 `data/processed/`。

### 2.2 不向 LLM 发送全量原始表

LLM 只能接收聚合指标 JSON、top N 结果和数据质量摘要。不能把 5 万条建筑记录直接发给模型。

### 2.3 风险分数不是结构安全结论

所有页面和报告中涉及 risk score / risk level 的地方，都必须出现类似说明：

```text
This is a rule-based screening indicator, not a structural inspection result.
```

中文界面对应：

```text
该结果是基于公开数据和规则模型的初步筛查指标，不等同于正式结构安全鉴定。
```

### 2.4 dashboard 不应依赖实时联网才能打开

首次开发可以联网下载官方数据，但 dashboard 默认应优先读取本地缓存。无网络时，应能使用已缓存数据或 sample 数据启动。

### 2.5 错误提示面向用户

页面不能直接暴露 Python traceback。错误提示应说明：

- 出错的数据源或模块。
- 可能原因。
- 用户可采取的下一步。

## 4. 模块责任边界

| 模块 | 责任 | 禁止事项 |
| --- | --- | --- |
| `src/data_sources/` | 官方数据下载、缓存、解压 | 不做业务指标 |
| `src/pipeline/` | 字段标准化、数据质量、聚合表生成 | 不写页面组件 |
| `src/models/` | 风险规则、区域指数 | 不调用 Streamlit |
| `src/dashboard/` | 图表、地图、UI 组件 | 不改原始数据 |
| `src/ai/` | prompt、LLM、模板摘要、输出检查 | 不读取全量原始 CSV |
| `src/reports/` | Markdown/HTML 报告 | 不重新计算核心指标 |
| `src/utils/` | 配置、日志、路径、通用工具 | 不放业务规则 |

## 5. 依赖选择规则

v1.0 默认依赖：

```text
pandas
numpy
streamlit
plotly
folium
streamlit-folium
requests
pyarrow
duckdb
python-dotenv
openai
pytest
```

暂缓引入：

- `geopandas`：只有在 district boundary 空间连接确实需要时再加入。
- 数据库服务：Phase 0-2 使用 Parquet + DuckDB。
- React / FastAPI：只有进入长期部署或多人协作时再升级。

## 6. 配置规则

`.env.example` 至少包含：

```text
OPENAI_API_KEY=
OPENAI_MODEL=
APP_DEFAULT_LANGUAGE=zh
DATA_CACHE_DIR=data/cache
DATA_RAW_DIR=data/raw
DATA_PROCESSED_DIR=data/processed
```

不得把 API Key 写入代码、测试数据或报告。

## 7. 日志规则

所有 pipeline 命令至少输出：

- 开始时间。
- 输入路径或 URL。
- 输出路径。
- 原始记录数。
- 有效记录数。
- 异常记录数。
- 结束时间。

日志既要能在命令行看到，也要能写入 `data/cache/pipeline_run.log`。

## 8. PR 执行规则

每个 PR 必须做到：

- 只解决一个明确任务。
- 更新相关测试。
- 更新或引用相关文档。
- 不混入无关重构。
- 不修改 `data/raw/` 中的官方原始数据。
- 若改变数据契约，必须同步更新 `01_数据指标口径.md`。

PR 描述必须包含：

```text
## What changed
## Why
## How to test
## Data/model contract impact
## Screenshots or output sample, if UI/report changed
```

### 8.1 大步冲刺执行规则

当需求文档或路线图明确把多个 PR 合并为一个产品切片时，可以按 sprint 方式连续推进，不必每个小页面改动都停下来等待确认。

适用条件：

- 该 sprint 已在 `docs/02_开发实施路线图.md` 或 `docs/08_产品体验优化规划.md` 中定义。
- 涉及的改动都服务同一个产品目标，例如 Phase 4 Sprint A 的“语言、Data Intake、Admin、报告工作台”。
- 不破坏已通过门禁的数据 pipeline、风险模型和报告导出契约。

执行要求：

- 每个 sprint 开始前先确认当前门禁状态和数据状态。
- 保持增量开发，不做无关重构。
- UI 改动必须同步测试、README 或使用说明。
- 涉及 API Key 或 LLM 配置时，不得把 Key 写入代码、报告、导出包或 git。
- sprint 结束必须运行 `python -m pytest` 和 `python -m src.pipeline.product_readiness`。
- sprint 通过后可以做阶段性 git checkpoint，commit message 需要说明阶段目标和主要交付。

## 9. 开发停止条件

遇到以下情况，需要先暂停对应分支开发并记录问题：

- 官方数据源 URL 失效。
- 官方字段发生重大变化。
- 楼龄解析率低于 90%。
- 18 区字段无法稳定识别。
- 风险模型输出大量 Unknown。
- dashboard 页面无法在缓存数据下启动。
- AI 输出出现无法通过规则过滤的过度结论。

暂停不是停止项目，而是先修数据契约或执行口径。

## 10. 后续开发优先级

第一优先级：

- Phase 0 数据底座。
- `buildings.parquet`。
- `district_metrics.parquet`。
- 验证脚本。

第二优先级：

- dashboard 核心页面。
- 地图和图表。
- 筛选联动。

第三优先级：

- MBIS/MWIS 监管信号。
- AI Report Studio。
- Markdown/HTML 报告。

第四优先级：

- PDF、高级云部署、用户系统、数据库、多用户协作。
