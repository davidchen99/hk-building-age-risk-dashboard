# 演示流程与截图清单

本文档用于导师汇报、研究组演示和产品交付说明。它假设 dashboard 已通过 `python -m src.pipeline.product_readiness`，并使用官方缓存数据。

## 1. 标准截图

截图生成命令：

```bash
python -m playwright install chromium
python -m src.pipeline.capture_dashboard_screenshots --base-url http://localhost:8501 --output-dir outputs/screenshots
```

当前标准截图位于：

| 截图 | 页面 | 用途 |
| --- | --- | --- |
| `outputs/screenshots/01_home_start.png` | Home / Start | 展示数据状态、任务入口和可用交付物 |
| `outputs/screenshots/02_portfolio_overview.png` | Portfolio Overview | 展示全港组合楼龄、用途和风险结构 |
| `outputs/screenshots/03_spatial_dashboard.png` | Spatial Dashboard | 展示区域 choropleth、图层状态和地图 |
| `outputs/screenshots/04_district_benchmark.png` | District Benchmark | 展示区域优先级排名和单区指标 |
| `outputs/screenshots/05_ai_report_studio.png` | AI Report Studio | 展示报告范围确认、模型版本和生成方式 |
| `outputs/screenshots/06_method_qa.png` | Method & QA | 展示方法审查、质量快照和导出入口 |
| `outputs/screenshots/screenshots_manifest.json` | 截图 manifest | 记录截图生成时间、页面和文件大小 |

## 2. 5 分钟演示脚本

### 0:00-0:40 打开产品和确认数据

打开 `http://localhost:8501`，停留在 `Home / Start`。

讲法：

- 当前使用官方缓存数据，不是 sample。
- 顶部状态标签显示 records、analysis year、data updated、filters 和 source。
- 数据规模为约 5.1 万栋建筑，MBIS notice 为约 2,300 条。
- 风险等级是规则化筛查，不是结构安全鉴定。

### 0:40-1:20 全港组合概览

进入 `Portfolio Overview`。

讲法：

- 先看楼龄分段、用途结构和风险等级结构。
- 图表说明明确了楼龄来自 occupation permit 日期。
- 综合风险在楼龄基线外加入用途、类型和匹配监管信号。

### 1:20-2:05 空间分布

进入 `Spatial Dashboard`。

讲法：

- 默认展示 district choropleth，不直接渲染全部点位。
- 建筑点位和 MBIS notice 是可选图层。
- `Layer Display Status` 说明当前展示的是区域层、完整集合还是抽样。
- 地图用于回答“哪里更值得关注”，不是给出工程安全结论。

### 2:05-2:45 区域优先级

进入 `District Benchmark`。

讲法：

- 默认表格只展示关键列，高级指标放在展开区。
- priority index 综合楼龄结构、50+ 占比、高/重点关注占比、MBIS 信号和数据质量。
- 可以用该页选择单区做后续维护优先级分析。

### 2:45-3:25 监管信号

进入 `Regulatory Signals`。

讲法：

- MBIS notice 是公开监管记录。
- 匹配置信度表示 notice 与建筑记录关联的可靠程度。
- MBIS notice rate 是每千栋建筑的监管信号密度，不是缺陷率。

### 3:25-4:25 报告生成

进入 `AI Report Studio`。

讲法：

- 生成前先确认当前记录数、筛选条件、数据更新时间、风险模型版本和 prompt 版本。
- Template 模式无需 API Key。
- 如配置 DeepSeek 或 OpenAI，需要先在 `Admin / Settings` 测试连接。
- LLM 不可用时自动 fallback 到 Template，不阻断 Markdown / HTML 导出。

### 4:25-5:00 方法审查和交付包

进入 `Method & QA`。

讲法：

- 这里集中展示方法、质量快照、数据源 manifest 和导出入口。
- `Generate full export package` 会生成完整交付包。
- 导出包包括 CSV、图表 HTML、报告和方法摘要，适合给导师或研究团队复查。

## 3. 中文研究汇报示例结构

题目建议：香港建筑资产老化风险筛查与维护优先级分析。

建议结构：

1. 研究背景：香港既有建筑资产规模大，公共数据可用于早期筛查。
2. 数据来源：BDBIAR 建筑年龄记录、18 区边界、MBIS 监管通知。
3. 方法：基于楼龄、用途、类型和监管信号的可解释规则评分。
4. 全港结果：楼龄结构、50+ 占比、高/重点关注风险分布。
5. 区域结果：Yau Tsim Mong、Sham Shui Po、Kowloon City 等优先级较高区域。
6. 监管信号：MBIS notice 匹配率与 notice density 作为辅助信号。
7. 局限性：公开数据筛查不等同于结构安全鉴定，需要结合现场检测、维修历史和结构资料。
8. 后续工作：补充维修记录、业权信息、实地调查和更强地图交互。

## 4. English Report Example Structure

Recommended title: Screening Ageing Risk and Maintenance Priorities in Hong Kong Building Assets.

Suggested sections:

1. Background: public building asset data can support early-stage ageing screening.
2. Data: BDBIAR building age records, district boundaries, and MBIS notices.
3. Method: explainable rule-based scoring using age, use, type, and regulatory signals.
4. Portfolio findings: age distribution, 50+ share, and high/critical screening share.
5. District priorities: compare top districts by priority index.
6. Regulatory signals: MBIS notice matching and density as supporting signals.
7. Limitations: screening outputs are not structural inspection findings.
8. Next steps: maintenance history, ownership, field inspection, and enhanced spatial interaction.
