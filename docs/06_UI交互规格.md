# UI 交互规格

本文档定义 v1.0 dashboard 的页面、组件、状态和交互要求。实现 UI 时以本文档为准。下一版体验优化的详细背景和 PR 顺序见 `docs/08_产品体验优化规划.md`。

## 1. 整体体验定位

界面应像研究分析 dashboard，而不是营销页面。

设计关键词：

- 清晰。
- 稳定。
- 信息密度适中。
- 适合反复筛选和比较。
- 方法限制可见。
- 图表和报告可直接用于研究汇报。

避免：

- 大幅 hero。
- 装饰性卡片堆叠。
- 过度渐变。
- 只展示好看的图但缺少口径。
- 把风险分数包装成正式工程结论。

## 2. 全局布局

建议结构：

```text
顶部：产品名称 + 数据版本 + 当前记录数 + 语言切换
左侧：导航 + 全局筛选
主体：当前页面内容
底部或方法页：数据源、模型版本、限制说明
```

全局筛选：

- district。
- territory。
- usage_group。
- type_group。
- age_band。
- risk_level。

筛选行为：

- 默认全选。
- 清空筛选后显示空状态。
- 提供 Reset filters。
- 筛选条件进入报告。

下一版增强：

- 新增 Home / Start 作为任务型入口页。
- 新增 Admin / Settings 作为管理员配置页。
- v1.0 的 8 个核心页面继续保留，Home 和 Admin / Settings 属于体验和配置支撑页。
- 顶部或侧边栏必须提供全局语言切换入口，建议使用 `中文 / EN` 或地球图标加文字。

## 2.1 Home / Start

目标：解决首次打开后不知道怎么开始的问题。

首页必须回答：

- 当前用的是什么数据。
- 数据是否足够可信。
- 用户下一步可以做什么。
- 当前有哪些可直接下载的交付物。

组件：

- 数据状态卡：Official cache / Uploaded data / Sample fallback。
- 核心规模卡：building records、MBIS notices、quality issue count。
- 数据健康卡：age parse rate、coordinate valid rate、MBIS match rate。
- 任务入口：
  - Full Hong Kong portfolio analysis。
  - Single district maintenance priority。
  - Use topic analysis。
  - Data quality review。
  - Generate research report。
- 可用导出物：export package、example report、acceptance report。
- 风险解释提示：rule-based screening, not structural inspection。

验收：

- 新用户不读 README 也能从首页进入一次完整分析。
- 首页默认不展示 manifest JSON、文件路径和字段明细。
- 无缓存或 sample fallback 时有清晰状态提示。

## 2.2 全局中英文切换

目标：让界面语言和报告语言都有明确控制。

要求：

- 提供全局 `中文 / EN` 切换。
- 页面标题、按钮、提示、状态标签、指标名称跟随界面语言。
- AI Report Studio 的报告语言默认跟随界面语言，但允许单独切换。
- 官方字段名、地名和导出文件名可以保留英文。
- 中英文文案必须表达同一业务含义，不允许只翻译部分页面。

验收：

- 切到中文后，主要操作路径不能继续大面积显示英文。
- 切到英文后，方法说明、报告生成和导出流程仍完整可用。

## 3. 页面状态

每个页面必须处理：

| 状态 | 要求 |
| --- | --- |
| Loading | 显示正在读取数据 |
| Empty | 说明当前筛选无结果 |
| Error | 显示用户可理解错误 |
| No cache | 提示运行 pipeline 或使用 sample |
| No API Key | AI 页面自动使用模板摘要 |
| Partial data | 显示数据质量提醒 |

禁止直接显示 Python traceback。

## 4. Data Intake

目标：让用户知道当前用的是什么数据，数据质量是否可用。

组件：

- 数据源状态卡。
- manifest 信息。
- 原始记录数。
- 有效记录数。
- 楼龄解析率。
- 坐标有效率。
- Unknown usage 数量。
- Unknown type 数量。
- 用户上传 CSV 入口。
- 数据预览表。

下一版增强：

- 默认展示数据健康摘要，不默认展开 manifest JSON。
- 技术细节放入展开项：source manifest、字段映射、文件路径、原始字段。
- 明确显示当前数据模式：Official cache、Uploaded data、Sample fallback。
- 用户上传数据后，必须提供恢复官方缓存数据的入口。
- 数据质量问题需要以可读标签和计数展示，不能只显示原始 JSON。

主要操作：

- 使用缓存数据。
- 上传 CSV。
- 查看字段映射。
- 下载数据质量摘要。

验收：

- 用户能判断当前数据能否用于分析。
- 缺数据时知道下一步该运行什么命令。
- 上传数据不会让用户误以为官方缓存被覆盖。

## 5. Portfolio Overview

目标：回答“整体建筑资产老化和风险结构如何”。

指标卡：

- Total Buildings。
- Median Age。
- 30+ Share。
- 50+ Share。
- High/Critical Share。
- Data Quality Score。

图表：

- Age band distribution。
- Risk level distribution。
- Usage distribution。
- Top 10 districts by median age。
- Top 10 districts by district priority index。

交互：

- 图表随全局筛选刷新。
- hover 显示数值和百分比。
- 指标单位明确。

## 6. Spatial Dashboard

目标：回答“老化和风险在哪里”。

地图层：

- Building points by risk_level。
- District choropleth by median_age。
- District choropleth by share_50_plus。
- District choropleth by district_priority_index。
- MBIS notice points。

控件：

- 图层开关。
- 风险等级筛选。
- 点位显示阈值提示。
- 地图图例。

点位 tooltip：

- Address。
- District。
- Usage。
- Type。
- Building age。
- Risk level。
- Risk reason。
- MBIS matched status。

性能策略：

- 默认优先显示区域 choropleth。
- 点位层在筛选后显示。
- 超过阈值时使用 clustering 或提示缩小筛选。
- 必须明确告知当前地图是全量、抽样、筛选后还是聚合展示。
- 图层开关应区分建筑点位、区域指标和 MBIS notice。

视觉要求：

- 地图图例必须可见。
- 风险颜色与全站风险等级保持一致。
- Tooltip 应像资产信息卡，而不是原始字段列表。
- MBIS notice 必须带监管记录说明，不直接表达结构危险结论。

当前实现状态：

- 默认开启 `District choropleth`，建筑点位和 MBIS notice 图层按数据量决定是否默认开启。
- 页面提供 `Layer Display Status`，显示每个图层的开启状态、展示记录数和性能说明。
- 建筑点位超过 `Building point cap` 时使用固定抽样并进入 clustering，不直接渲染全量 5 万点。
- MBIS notice 按当前筛选范围内可关联建筑过滤，避免单区或用途分析时仍显示全港监管点。
- 区域图层不同指标使用不同颜色阈值，图例跟随当前指标变化。

## 7. District Benchmark

目标：回答“哪些区应优先关注”。

组件：

- 18 区 ranking table。
- 指标排序。
- 区域详情面板。
- 区域楼龄分布。
- 区域用途结构。
- 区域风险结构。

Ranking 表字段：

- district_en。
- total_buildings。
- median_age。
- share_50_plus。
- high_critical_share。
- mbis_notice_rate。
- district_priority_index。
- data_quality_score。

交互：

- 点击区名更新详情。
- 支持导出 ranking CSV。

## 8. Use & Typology

目标：回答“不同用途和建筑类型的老化压力有什么差异”。

组件：

- usage_group 风险分布。
- usage_group 楼龄分布。
- Tower / Podium 对比。
- 用途 x district heatmap。
- 用途 x age_band 交叉表。

交互：

- 选择用途后同步筛选其他页面。
- 支持导出交叉表。

## 9. Regulatory Signals

目标：回答“监管通知信号如何影响维护优先级”。

组件：

- MBIS notice count。
- MBIS notice rate by district。
- Notice points map。
- Matching confidence distribution。
- Matched / unmatched table。

说明必须可见：

```text
MBIS notices are regulatory records and should not be interpreted as direct proof of structural defect.
```

中文：

```text
MBIS 通知是监管记录，不应直接解释为结构缺陷或危险建筑结论。
```

## 10. AI Report Studio

目标：把 dashboard 分析转成可导出的研究报告。

控件：

- 语言：中文 / English。
- 报告范围：全港 / 当前筛选 / 单区 / 用途专题。
- 报告类型：Executive Summary / Research Note / Maintenance Priority Brief / Data Quality Memo。
- 生成方式：Template / DeepSeek / OpenAI / Local。
- 生成按钮。
- 导出 Markdown。
- 导出 HTML。

报告生成前必须展示：

- 当前筛选条件。
- 当前记录数。
- 数据版本。
- 风险模型版本。
- prompt 版本。
- 摘要生成方式。
- 是否使用 fallback。

输出结构：

- Overall Risk Summary。
- Key Observations。
- Maintenance Priorities。
- Regulatory Signals。
- Data Limitations。
- Method Note。

状态：

- 无 API Key：默认 Template。
- LLM 失败：fallback Template。
- 输出审查失败：提示并 fallback。

下一版增强：

- 页面结构应更像报告工作台，而不是只提供一个摘要按钮。
- 生成前先确认报告范围和数据版本。
- 生成后展示结构化报告预览。
- 导出后显示报告路径、文件大小、生成时间和下载入口。
- DeepSeek / OpenAI 配置不在该页直接完成，只读取 Admin / Settings 的配置状态。

验收：

- 用户能在导出前确认报告基于哪个筛选范围。
- 报告预览中必须包含方法限制和监管信号边界。
- LLM 不可用时用户仍能完成模板报告导出。

## 10.1 Admin / Settings

目标：让管理员配置 LLM provider、API Key 和连接测试。

组件：

- Provider 选择：Template、DeepSeek、OpenAI、Local。
- API Key 输入。
- Base URL 输入。
- Model name 输入或选择。
- Test connection 按钮。
- 当前连接状态。
- 上一轮 LLM 调用状态。
- fallback 状态提示。

安全要求：

- API Key 不进入报告。
- API Key 不进入导出包。
- API Key 不应在页面明文回显。
- 如需本地持久化，必须写入 `.gitignore` 覆盖的本地配置。

验收：

- 无 Key 时 Template 模式可用。
- DeepSeek 配置后可测试连接。
- 连接失败时给出可理解错误，并不影响模板摘要。

## 11. Method & QA

目标：让用户和研究审查者知道方法是否可信。

内容：

- 数据源列表。
- 数据版本。
- 风险模型版本。
- prompt 版本。
- 字段映射表。
- 风险评分规则。
- 数据质量指标。
- MBIS 匹配方法。
- 已知限制。

必须支持：

- 下载方法摘要。
- 下载数据质量摘要。

## 12. 报告导出体验

导出前显示：

- 当前筛选条件。
- 当前记录数。
- 使用的数据版本。
- 使用的模型版本。
- 摘要生成方式。

导出后显示：

- 报告路径。
- 生成时间。
- 文件大小。

## 13. v1.0 UI 完成标准

v1.0 UI 必须满足：

- 8 个核心页面都可访问。
- 所有页面有空状态。
- 所有页面有错误状态。
- 全局筛选可用。
- 主要图表有单位和标题。
- 风险解释和限制说明可见。
- 报告可导出。
- 用户不看代码也能完成一次完整分析。

## 14. 下一版体验增强完成标准

下一版体验增强完成后，必须满足：

- 用户打开 dashboard 后首先看到任务型入口或明确的新手引导。
- 全局语言切换覆盖主要页面标题、按钮、提示、状态标签和指标说明。
- Data Intake 默认展示数据健康和数据模式，manifest 等技术细节默认折叠。
- AI Report Studio 展示报告范围、数据版本、模型版本、prompt 版本和生成方式。
- Admin / Settings 可以配置 DeepSeek / OpenAI / Template，并测试连接。
- 地图默认说明当前展示模式：区域层、点位层、抽样或 clustering。
- 每个核心页面第一屏都能说明“本页回答什么问题”。
- 主要导出动作都有明确的路径、文件大小、生成时间和下载入口。
- 演示路径和截图可支持 5 分钟研究汇报。
