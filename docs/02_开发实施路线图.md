# 开发实施路线图

本文档用于后续批量 PR 和自动化执行。开发时优先按本文档顺序推进，不要跳过数据底座直接做 UI。

## 1. 总体阶段

| Phase | 目标 | 交付 |
| --- | --- | --- |
| Phase 0 | 数据可行性与底座 | 官方数据下载、标准化、Parquet、验证脚本 |
| Phase 1 | Dashboard 产品基线 | 核心页面、地图、图表、筛选、模板报告 |
| Phase 2 | 监管信号与 AI 报告 | MBIS 接入、匹配、监管专题、LLM 摘要 |
| Phase 3 | v1.0 成品验收与交付打磨 | 指标验证、图表导出、示例报告、方法文档 |
| Phase 4 | 产品体验增强 | 新手入口、全局中英文、Admin/Settings、报告工作台、演示材料 |

## 2. Phase 0：数据底座

### PR-01 项目骨架

内容：

- 创建 Python 项目结构。
- 添加 `requirements.txt`。
- 添加 `.env.example`。
- 添加 README 初稿。
- 创建 `src/`、`tests/`、`data/`、`outputs/` 目录。

验收：

- `python -m pytest` 可以运行，哪怕初始无测试。
- `README.md` 说明安装和启动方式。

### PR-02 官方 building age 下载

内容：

- 实现 `src/data_sources/fetch_bdbiar.py`。
- 下载官方 zip。
- 解压到 `data/raw/bdbiar/`。
- 记录 manifest。

验收：

```bash
python -m src.data_sources.fetch_bdbiar --force
```

应生成：

- 原始 zip。
- 解压 CSV。
- `data/cache/source_manifest.json`。

### PR-03 字段标准化与楼龄计算

内容：

- 实现 `src/pipeline/normalize_buildings.py`。
- 按 `01_数据指标口径.md` 映射字段。
- 解析 OP 日期。
- 计算楼龄和 age_band。
- 输出 `data/processed/buildings.parquet`。

验收：

```bash
python -m src.pipeline.normalize_buildings
python -m src.pipeline.validate_outputs
```

要求：

- 记录数大于 0。
- 楼龄解析率大于 90%。
- 18 区字段可识别。

### PR-04 风险评分 v0.2

内容：

- 实现 `src/models/risk_rules.py`。
- 增加 `risk_score`、`risk_level`、`risk_reason`。
- 增加单元测试。

验收：

```bash
pytest tests/test_risk_rules.py
```

边界值必须覆盖：

- 29/30 年。
- 39/40 年。
- 49/50 年。
- 59/60 年。
- Unknown age。

### PR-05 区域指标聚合

内容：

- 实现 `src/pipeline/build_district_metrics.py`。
- 输出 `data/processed/district_metrics.parquet`。
- 实现区域优先级指数 Phase 1 版本。

验收：

- 输出 18 区。
- 每个区有 total_buildings、median_age、share_50_plus、district_priority_index。
- 指标无除零错误。

## 6. 并行开发规则

可以并行：

- PR-06 和 PR-02/03 可部分并行，但 UI 只能用 sample 数据临时占位。
- PR-14 可在 PR-08 后启动，不必等 MBIS。
- PR-18 可在核心页面稳定后启动。

不能并行或不建议提前做：

- PR-09 不应早于 PR-03。
- PR-10 不应早于 PR-05。
- PR-13 不应早于 PR-12。
- PR-16 不应早于 PR-14。
- PR-24 Admin / Settings 可以和 PR-21 Home 并行，但 PR-25 AI Report Studio 工作台化应在 PR-24 后整合 LLM 配置状态。
- PR-27 视觉系统统一应放在主要体验页面落地后，避免重复调整样式。

## 7. Phase 4：产品体验增强

Phase 4 的目标是把已经跑通的 v1.0 功能闭环打磨成新手更容易使用、研究团队更容易演示的产品体验。详细体验要求见 `docs/08_产品体验优化规划.md`。

### PR-21 Home / Start 页面

内容：

- 新增任务型首页。
- 展示当前数据状态、核心数据规模、数据健康和可用导出物。
- 提供全港分析、单区分析、用途专题、数据质量审查和报告生成入口。

验收：

- 新用户不读 README 也能从首页开始一次完整分析。
- 首页不默认展示 manifest JSON 和技术路径。
- 数据缺失、sample fallback、官方缓存状态都能被明确识别。

### PR-22 全局中英文切换

内容：

- 增加全局 `中文 / EN` 切换入口。
- 统一主要页面标题、按钮、提示、状态标签和指标名称。
- AI Report Studio 报告语言默认跟随界面语言，并允许单独调整。

验收：

- 切到中文后，主要操作路径没有大面积英文残留。
- 切到英文后，报告生成和方法说明仍完整可用。

### PR-23 Data Intake 体验重构

内容：

- 将 Data Intake 默认视图改为数据健康面板。
- 默认展示数据模式、记录数、楼龄解析率、坐标有效率、质量问题数量。
- 将 source manifest、字段映射、文件路径和原始 JSON 放入展开区。

验收：

- 非技术用户能判断当前数据是否可用于分析。
- 用户上传 CSV 后能明确恢复官方缓存。

### PR-24 Admin / Settings 面板

内容：

- 增加 LLM Provider 配置：Template、DeepSeek、OpenAI、Local。
- 增加 API Key、Base URL、Model name 输入。
- 增加 Test connection。
- 显示当前连接状态和 fallback 状态。

验收：

- 无 Key 时 Template 模式仍可用。
- DeepSeek 配置后可测试连接。
- Key 不进入报告、导出包或明文回显。

### PR-25 AI Report Studio 工作台化

内容：

- 生成前展示报告范围、筛选条件、记录数、数据版本、模型版本和 prompt 版本。
- 生成后展示结构化报告预览。
- 导出后显示路径、文件大小、生成时间和下载入口。

验收：

- 用户能确认报告基于哪个数据范围。
- LLM 失败时自动 fallback Template。
- 报告中保留监管信号边界和方法限制。

### PR-26 Spatial Dashboard 体验优化

内容：

- 优化图层开关：区域层、建筑点位、MBIS notice。
- 明确点位展示阈值、抽样、clustering 状态。
- tooltip 改为资产卡片式信息。

验收：

- 官方数据量下地图不直接卡死。
- 用户能理解当前地图展示模式。

### PR-27 视觉系统和页面文案统一

内容：

- 统一指标卡、状态标签、按钮层级、空状态和错误状态。
- 每页第一屏说明本页回答什么问题。
- 技术 JSON 默认折叠，业务摘要优先展示。

验收：

- 页面不再像工程后台。
- 主要指标都有单位和解释。

### PR-28 截图、演示流程和交付材料

内容：

- 补 dashboard 截图。
- 编写 5 分钟演示脚本。
- 补中英文示例报告说明。

验收：

- 可按演示脚本完成一次全港、单区、用途专题和报告导出展示。
- 截图可用于研究汇报或导师沟通。

## 8. 下一步执行建议

当前 v1.0 功能闭环已经跑通后，下一步优先启动：

```text
PR-21 -> PR-22 -> PR-23 -> PR-24 -> PR-25
```

原因是这五项直接解决首次打开不会用、语言不统一、Data Intake 太技术化、DeepSeek 配置不产品化、报告页不够像工作台的问题。

### 8.1 Phase 4 Sprint A：大步产品化冲刺

PR-21 已完成后，下一轮可以按一个完整产品切片推进，而不是逐个小点停顿。Sprint A 建议合并推进：

```text
PR-22 全局中英文切换
PR-23 Data Intake 体验重构
PR-24 Admin / Settings 面板
PR-25 AI Report Studio 工作台化
```

Sprint A 的完成标准：

- 全局语言入口可用，主要页面文案能按中文 / English 切换。
- Data Intake 默认是数据健康视图，manifest、字段映射、文件路径等技术细节默认折叠。
- Admin / Settings 可配置 Template、DeepSeek、OpenAI，并能测试连接状态。
- AI Report Studio 能读取配置状态，生成前展示报告范围、筛选条件、数据版本、模型版本和 prompt 版本。
- LLM 不可用时继续 fallback Template，不阻断报告导出。
- `python -m pytest`、`python -m src.pipeline.product_readiness` 通过。
- README、使用说明和 UI 规格同步更新。

Sprint A 完成并通过成品门禁后，可以做一次阶段性 git checkpoint，作为后续继续冲刺前的稳定回退点。

随后再推进：

```text
PR-26 -> PR-27 -> PR-28
```

这三项负责地图体验、视觉统一和演示交付材料。

### 8.2 Phase 4 Sprint B：地图体验优化

PR-26 已作为 Sprint B 的第一步落地，范围限定在 `Spatial Dashboard`，不改变官方数据 pipeline、风险模型和报告导出契约。

已完成：

- 默认优先展示 district choropleth，避免首次打开直接渲染 5 万级点位。
- 增加 `District choropleth`、`Building points`、`MBIS notice layer` 图层开关。
- 增加 `Building point cap` 和 `MBIS point cap`，超过上限时使用固定抽样并通过 clustering 展示。
- 增加 `Layer Display Status`，明确每个图层当前是关闭、完整筛选集合，还是聚合抽样。
- 区域图层按不同指标使用不同颜色阈值，避免 priority、median age、50+ share、MBIS rate 共用错误口径。
- 建筑点位 tooltip 升级为资产信息卡，包含 address、district、usage、type、building age、risk level、risk reason、MBIS matched status。
- MBIS notice tooltip 明确监管记录不等同于结构缺陷结论。

Sprint B 后续优先级：

```text
PR-27 视觉系统和页面文案统一 -> PR-28 截图、演示流程和交付材料
```
