# v1.0 成品交付规格

本文档定义本项目 v1.0 成品的交付边界。后续开发不是只做 MVP，而是按 v1.0 成品交付推进。Phase 0-3 只是工程实施顺序，不代表最终只交付某个早期原型。

## 1. v1.0 产品定位

v1.0 产品定位为：

```text
面向香港私人建筑资产老化、维护优先级和 AI 辅助报告生成的研究级 dashboard 产品。
```

它必须能够真实运行、真实接入官方公开数据、完成完整分析流程，并输出可用于研究汇报和后续论文材料整理的报告。

## 2. v1.0 交付形态

v1.0 默认交付为本地可运行的 Streamlit dashboard 产品，而不是云端 SaaS。

交付形态包括：

- 本地 dashboard 应用。
- 命令行数据 pipeline。
- 官方数据缓存与处理后数据。
- 多页面分析 dashboard。
- AI / 模板双模式报告生成。
- Markdown / HTML 报告导出。
- 测试脚本和验收清单。
- README 和方法说明。

默认不包含：

- 多用户登录。
- 权限系统。
- 长期公网部署。
- 数据库后台服务。
- 租户隔离。
- 付费产品化运营功能。

如果后续要转为在线平台，可作为 v2.0 单独升级。

## 3. v1.0 必须完成的功能

### 3.1 数据接入

必须支持：

- 官方 `Building information and age records` 下载、解压、缓存。
- 18 区边界数据下载和缓存。
- MBIS issued notice 数据下载和缓存。
- 用户上传 CSV。
- sample 数据 fallback。
- manifest 记录数据源、下载时间、文件路径、记录数。

完成标准：

- 无网络时可使用缓存数据打开 dashboard。
- 有网络时可刷新官方数据。
- 用户上传数据不会破坏官方缓存。

### 3.2 数据处理

必须支持：

- 官方字段标准化。
- OP 日期解析。
- 楼龄计算。
- age band 生成。
- 用途和建筑类型标准化。
- 坐标有效性检查。
- 数据质量 flags。
- 个体风险评分。
- 区域指标聚合。
- 区域优先级指数。
- MBIS 地址/空间匹配。

完成标准：

- 生成 `buildings.parquet`。
- 生成 `district_metrics.parquet`。
- 生成 `regulatory_notices.parquet`。
- 生成 `source_manifest.json`。
- `validate_outputs` 命令通过。

### 3.3 Dashboard 页面

v1.0 必须包含以下页面：

| 页面 | 必须交付 |
| --- | --- |
| Data Intake | 数据源、manifest、质量摘要、上传入口 |
| Portfolio Overview | 全港/筛选范围核心指标、楼龄/用途/风险图表 |
| Spatial Dashboard | 点位地图、风险颜色、区域 choropleth 或区域层指标 |
| District Benchmark | 18 区 ranking、区域详情、优先级指数 |
| Use & Typology | 用途和 Tower/Podium 类型分析 |
| Regulatory Signals | MBIS 通知点位、匹配率、区域通知密度 |
| AI Report Studio | 语言选择、报告类型、模板/LLM 摘要、导出 |
| Method & QA | 数据源、模型规则、数据质量、限制说明 |

完成标准：

- 所有页面可以从导航访问。
- 筛选状态在页面间保持一致或明确重置。
- 页面空状态、错误状态、加载状态完整。

### 3.4 报告生成

必须支持：

- 中文模板摘要。
- 英文模板摘要。
- 有 API Key 时的 LLM 摘要。
- 无 API Key 时的 fallback。
- Markdown 导出。
- HTML 导出。
- 当前筛选条件进入报告。
- 数据版本、模型版本、prompt 版本进入报告。

完成标准：

- 报告不依赖手工复制。
- 报告包含方法限制。
- 报告中不出现“正式结构安全鉴定”之类过度表述。

### 3.5 测试和验收

必须支持：

- 单元测试。
- 数据验证脚本。
- dashboard 人工验收流程。
- 示例报告。
- README 操作说明。

完成标准：

```bash
python -m src.pipeline.build_all --use-cache
python -m src.pipeline.validate_outputs
pytest
streamlit run app.py
```

以上流程可以跑通。

## 4. v1.0 不接受的交付状态

以下状态不能算 v1.0 完成：

- 只能打开页面，但没有官方数据 pipeline。
- 只能用模拟数据，不能处理官方 zip。
- 图表能显示，但风险模型没有测试。
- AI 摘要能生成，但没有模板 fallback。
- 报告能导出，但没有数据版本和方法限制。
- dashboard 必须联网才能打开。
- 报错直接显示 Python traceback。
- 所有逻辑写在 `app.py` 里，无法维护。
- 没有 `validate_outputs`。
- 没有 README 或用户无法按说明运行。

## 5. v1.0 质量目标

### 5.1 数据质量

- 官方建筑记录读取成功。
- 楼龄解析率大于等于 90%。
- 坐标有效率大于等于 80%。
- 18 区识别完整。
- 风险等级没有异常值。

### 5.2 性能

- 从 Parquet 读取数据 5 秒以内。
- 筛选刷新 2 秒左右。
- 地图不因 5 万点直接卡死。
- 报告生成 10 秒以内，不含 LLM 网络时间。

### 5.3 可用性

- 第一次打开有明确引导。
- 页面有空状态。
- 网络失败有缓存 fallback。
- 无 API Key 有模板 fallback。
- 用户能在 10 分钟内完成一次完整分析和报告导出。

### 5.4 研究可复现性

- 数据版本可追踪。
- 风险模型版本可追踪。
- prompt 版本可追踪。
- 指标公式可在文档中找到。
- 导出报告可说明数据限制。

## 6. v1.0 最终验收场景

最终验收必须跑通以下完整用户旅程：

### 6.1 全港组合分析

1. 启动 dashboard。
2. 使用官方缓存数据。
3. 查看全港建筑楼龄和风险概览。
4. 查看 18 区排名。
5. 生成中文报告。
6. 导出 Markdown 和 HTML。

### 6.2 单区维护优先级分析

1. 选择一个 district，例如 `Yau Tsim Mong`。
2. 查看该区楼龄分布。
3. 查看该区高风险建筑用途结构。
4. 查看 MBIS regulatory signals。
5. 生成维护优先级摘要。
6. 导出报告。

### 6.3 用途专题分析

1. 选择 `Industrial` 或 `Office/Commercial`。
2. 对比不同区的高龄比例。
3. 查看风险等级分布。
4. 输出用途专题报告。

### 6.4 数据质量审查

1. 进入 Method & QA。
2. 查看 OP 日期缺失率。
3. 查看坐标有效率。
4. 查看 MBIS 匹配率。
5. 导出数据质量摘要。

## 7. 成品交付包

v1.0 交付包必须包含：

```text
app.py
requirements.txt
.env.example
README.md
需求文档.md
docs/
src/
tests/
data/sample/
outputs/reports/example_report.md
outputs/reports/example_report.html
```

不建议把官方大数据文件直接提交到 git。官方数据应通过 pipeline 下载或放入本地缓存目录。

## 8. 成品判断

当以下条件全部满足时，可以认为 v1.0 成品可交付：

- Phase 0-3 所有验收通过。
- v1.0 必须页面全部存在。
- 官方数据 pipeline 可复现。
- AI 和模板报告都可用。
- 用户按 README 能独立运行。
- 报告可以用于研究汇报。
- 代码结构可继续维护和扩展。
