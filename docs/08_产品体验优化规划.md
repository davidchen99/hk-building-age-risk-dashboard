# 产品体验优化规划

本文档记录当前 dashboard 在真实试用后暴露出的体验问题，并定义下一版体验优化的产品方向、优先级、交付项和验收标准。它不替代 `docs/04_v1成品交付规格.md`，而是在 v1.0 功能闭环基础上，把产品从“工程可用”推进到“新手好用、研究团队愿意反复使用”。

## 1. 当前版本判断

当前版本已经具备完整分析闭环：

- 官方数据接入、缓存、清洗和验证。
- 建筑楼龄、风险评分、区域指标和 MBIS 监管信号。
- 8 个核心 dashboard 页面。
- AI / 模板摘要。
- Markdown / HTML 报告导出。
- 导出包、验收脚本和成品门禁。

但当前体验仍偏工程后台：

- 首次打开缺少明确的任务入口。
- 全局中英文体验不统一。
- 页面偏干，技术信息和业务信息没有充分分层。
- 用户需要自己理解页面顺序，缺少推荐工作流。
- AI Report Studio 更像功能面板，不像报告工作台。
- LLM API Key 配置还没有产品化入口。
- 地图和大数据量展示仍有继续优化空间。
- 演示流程、截图和研究汇报路径仍需补齐。

## 2. 下一版体验目标

下一版目标不是增加更多底层算法，而是提升可用性、专业感和研究交付效率。

目标：

- 新手打开 30 秒内知道当前数据是否可用、下一步点哪里。
- 非技术用户能按任务入口完成一次全港、单区或用途专题分析。
- 中文和英文界面体验一致，报告语言与界面语言可清楚区分。
- 数据源、模型、限制说明可见，但不压迫主流程。
- 报告生成流程像正式工作台，而不是单个摘要按钮。
- DeepSeek / OpenAI / Template 等生成方式有管理员配置和测试入口。
- 地图在 5 万级数据下保持可理解、可操作。
- 导出材料可直接用于导师汇报、研究组讨论或论文材料整理。

## 3. 体验设计原则

### 3.1 专业而不营销化

界面应像研究分析工具，不做大幅 hero、浮夸渐变或营销式介绍。视觉重点是清晰、稳定、可比较。

### 3.2 任务优先于模块

底层仍保留 Data Intake、Portfolio、Spatial、District 等专业模块，但第一层入口应围绕用户任务：

- 全港资产老化概览。
- 单区维护优先级分析。
- 用途专题分析。
- 数据质量审查。
- 报告生成与导出。

### 3.3 技术信息分层

Manifest、文件路径、字段映射、模型 JSON 等信息需要保留，但默认不直接压到用户面前。默认展示业务摘要，技术细节放在展开区域或 Method & QA。

### 3.4 风险解释始终克制

风险分数必须持续表达为 public-data screening，不得暗示结构安全鉴定、危险建筑结论或工程检测结果。

## 5. Home / Start 设计要求

目标：让用户知道“这个产品现在能不能用、我应该从哪里开始”。

首页应包含：

- 数据状态摘要：官方缓存 / 用户上传 / sample。
- 核心数据量：建筑记录数、监管通知数、数据质量问题数。
- 数据质量信号：楼龄解析率、坐标有效率、MBIS 匹配率。
- 任务入口：
  - 全港组合分析。
  - 单区维护优先级。
  - 用途专题分析。
  - 数据质量审查。
  - 生成研究报告。
- 可用导出物：示例报告、导出包、验收报告。
- 风险解释短提示：本系统是规则化筛查，不是结构安全鉴定。

验收标准：

- 新用户不需要读 README，也能从首页进入核心分析。
- 首页不展示大段 JSON 或技术路径。
- 首页能明确提示数据缺失、sample 数据或官方缓存状态。

## 6. 全局中英文切换

目标：界面语言、报告语言和数据字段语言有清楚边界。

要求：

- 顶部或侧边栏提供语言切换入口，建议使用 `中文 / EN` 或地球图标加文字。
- 全局页面标题、按钮、提示、状态标签、指标名跟随界面语言切换。
- AI Report Studio 中的报告语言可以默认跟随界面语言，但允许单独选择。
- 数据字段和官方英文地名可保留英文，不强行翻译专有字段。
- 中英文文案必须表达一致，不能只翻译部分页面。

验收标准：

- 用户切到中文后，不应仍看到大面积英文操作文案。
- 用户切到英文后，报告工作台和方法说明仍可完整使用。

## 7. Admin / Settings 面板

目标：把 LLM 配置从命令行和环境变量体验，提升为可理解的管理员配置体验。

应支持：

- Provider：Template、DeepSeek、OpenAI、Local。
- API Key 输入框。
- Model name 输入或选择。
- Base URL 输入，DeepSeek 需要支持自定义 API base。
- Test connection。
- 当前连接状态。
- 上一轮 LLM 调用状态。
- 失败时 fallback 到 Template 的提示。

安全要求：

- API Key 不进入报告。
- API Key 不写入导出包。
- 如果需要持久化，只能写入本地 `.env` 或本地配置文件，并加入 `.gitignore`。
- 页面不得明文展示完整 Key，只显示 masked 状态。

验收标准：

- 无 Key 时 Template 模式可用。
- DeepSeek 配置后可以测试连接。
- LLM 失败时用户能看到原因，并可继续使用模板摘要。

## 8. AI Report Studio 体验升级

目标：从“生成摘要按钮”升级为“研究报告工作台”。

报告生成前应展示：

- 当前分析范围。
- 当前筛选条件。
- 当前记录数。
- 数据版本。
- 风险模型版本。
- prompt 版本。
- 生成方式。

报告生成流程：

1. 选择报告范围。
2. 选择报告类型。
3. 选择语言。
4. 选择生成方式。
5. 预览将进入报告的核心指标。
6. 生成摘要。
7. 预览报告结构。
8. 导出 Markdown / HTML。

报告预览应结构化展示：

- Overall Risk Summary。
- Key Observations。
- Maintenance Priorities。
- Regulatory Signals。
- Data Limitations。
- Method Note。

验收标准：

- 用户能在导出前确认报告范围和数据版本。
- 导出后显示路径、文件大小、生成时间和下载入口。
- 报告不会把 MBIS notice 解释为结构缺陷事实。

## 9. 地图体验优化

目标：让地图回答“哪里更值得关注”，而不是只展示大量点。

要求：

- 默认优先展示区域 choropleth。
- 建筑点位作为可选图层。
- MBIS notice 作为可选图层。
- 点位超过阈值时给出提示，并默认 clustering 或抽样。
- tooltip 显示资产卡片化信息：
  - Address。
  - District。
  - Usage。
  - Type。
  - Building age。
  - Risk level。
  - Risk reason。
  - MBIS matched status。
- 图例必须始终可见。

验收标准：

- 全量官方数据下地图不应直接卡死。
- 用户能理解当前地图展示的是全量、抽样还是筛选后数据。

## 10. 视觉与文案优化

目标：让页面从“能看”变成“愿意用”。

要求：

- 指标卡使用统一结构：指标名、数值、单位、解释。
- 状态用标签表达：Official cache、Uploaded data、Sample fallback、Template mode、LLM ready。
- 页面说明短句化，避免长段技术描述。
- 风险限制说明固定位置可见，但不重复到干扰阅读。
- 技术 JSON 默认放进展开面板。
- 表格默认展示关键列，高级字段可展开。
- 颜色系统保持克制，风险色保持一致。

验收标准：

- 每个页面第一屏能说明“这个页面回答什么问题”。
- 用户不需要看代码就能理解主要指标含义。

### 12.1 Sprint A：语言、配置与报告工作台

PR-21 Home / Start 完成后，下一步可以把 PR-22 到 PR-25 作为一个连续产品化冲刺推进：

- PR-22 全局中英文切换。
- PR-23 Data Intake 体验重构。
- PR-24 Admin / Settings 面板。
- PR-25 AI Report Studio 工作台化。

这四项属于同一个用户体验链路：用户打开产品后，能用合适语言理解数据状态，在 Data Intake 判断数据是否可信，在 Admin / Settings 配置 DeepSeek 或 OpenAI，并在 AI Report Studio 生成可导出的研究报告。

Sprint A 不应改动核心风险模型和官方数据处理契约。除非为了接入配置状态，否则不重写 `src/pipeline/`、`src/models/` 或报告渲染核心逻辑。

Sprint A 验收：

- 中文 / English 全局切换覆盖主要页面。
- Data Intake 默认呈现业务化数据健康视图。
- Admin / Settings 能配置和测试 Template、DeepSeek、OpenAI。
- AI Report Studio 能展示报告范围、数据版本、模型版本、prompt 版本和生成方式。
- 无 API Key 或 LLM 失败时，Template fallback 仍能导出 Markdown / HTML。
- 成品门禁通过后形成阶段性 checkpoint。

### 12.2 Sprint B：地图体验优化

PR-26 已落地为地图体验优化切片。当前 Spatial Dashboard 不再默认直接展示大量点位，而是以区域分级图层为第一视角，并把建筑点位和 MBIS notice 作为可选图层。

已落地体验：

- 地图第一屏新增图层控制区和展示状态表。
- 默认展示 district choropleth，可切换 priority index、median age、50+ share、MBIS notice rate。
- 建筑点位和 MBIS notice 图层可独立开启。
- 点位数量超过上限时固定抽样并 clustering，页面明确显示抽样数量。
- 建筑 tooltip 采用资产卡片信息，补充 risk reason 和 MBIS matched status。
- MBIS tooltip 明确监管通知不是结构缺陷结论。

Sprint B 剩余工作不再继续扩地图底层能力，优先进入 PR-27 和 PR-28：

- PR-27：统一视觉系统、指标卡、状态标签、页面第一屏说明和中文/英文文案。
- PR-28：补 dashboard 截图、5 分钟演示流程、中文研究汇报示例和英文研究报告示例。

### 12.3 Sprint C：视觉系统第一切片

PR-27 已完成第一切片，重点不是大改信息架构，而是先统一基础观感和新手理解入口。

已落地体验：

- 指标卡增加统一边框、留白和更稳定的视觉层级。
- 顶部分析范围改为状态标签，而不是一整行技术 caption。
- 每个页面第一屏增加简短说明，明确该页回答的问题。
- 首页和地图页的页面说明、状态标签已进入 app smoke 自动化测试。

已继续深化：

- 表格默认列和高级列展开策略已覆盖 Data Intake、District Benchmark、Regulatory Signals、Method & QA。
- 图表标题、单位、解释和风险说明已覆盖 Portfolio、Use & Typology、Regulatory Signals。
- 中文界面已补齐主要任务卡、按钮、图表标题、AI Report 控件和下载动作。
- 风险压力、数据可用性、监管覆盖已形成统一状态标签。

## 13. 下一版完成标准

下一版体验优化完成后，必须满足：

- 新用户能从 Home 页完成一次完整分析路径。
- 全局中英文切换覆盖主要页面。
- DeepSeek API Key 可在 Admin / Settings 中配置并测试。
- AI Report Studio 能清楚展示报告范围、数据版本和生成方式。
- Method & QA 能继续提供研究复现和导出包。
- 地图在官方数据量下有清楚的图层和性能提示。
- 演示截图和 5 分钟演示脚本可用于对导师或研究团队展示。
