# 数据与指标口径

本文档冻结后续开发所需的数据字段、清洗规则、指标公式和风险评分口径。实现细节若与主需求文档早期章节冲突，以本文档为准。

## 1. 官方数据源

### 1.1 建筑年龄主表

数据源：Building information and age records  
提供机构：Buildings Department  
用途：主建筑资产表、楼龄计算、用途和区域分析  
下载入口：

```text
https://static.csdi.gov.hk/csdi-webpage/download/0e55c533715b5da3ae0ca6e6024e90b4/csv
```

注意：该入口下载结果实际为 zip 包，需解压后读取 CSV。

### 1.2 18 区边界

数据源：District boundary  
提供机构：Home Affairs Department  
用途：区域地图、空间校验、choropleth  
下载入口：

```text
https://www.had.gov.hk/psi/hong-kong-administrative-boundaries/hksar_18_district_boundary.json
```

### 1.3 MBIS 通知

数据源：Statutory Notices issued on prescribed inspection/repair for buildings  
提供机构：Buildings Department  
用途：监管信号、维护优先级增强、区域通知密度  
WFS CSV 入口：

```text
https://portal.csdi.gov.hk/server/services/common/bd_rcd_1631168029910_44937/MapServer/WFSServer?service=wfs&request=GetFeature&typename=BDMBIS&outputFormat=CSV
```

## 3. 字段标准化规则

### 3.1 文本字段

- 去除前后空格。
- 空字符串、`N/A`、`NA`、`NULL`、`-` 统一转为空值。
- 英文字段保留官方大小写用于展示，匹配字段另生成 uppercase 版本。
- 中文字段不做繁简转换，除非后续明确需要。

### 3.2 日期字段

`occupation_permit_date` 来自 `NSEARCH3_E`。

解析规则：

- 标准格式：`YYYY-MM-DD`。
- 解析失败则置空，并添加 `invalid_op_date` 到 `data_quality_flags`。
- `occupation_permit_year` 从日期中提取年份。
- 若年份大于 `analysis_year`，置为空并标记 `future_op_date`。

`analysis_year` 默认取系统当前年份；为保证研究复现，pipeline 允许传入固定年份：

```bash
python -m src.pipeline.build_all --analysis-year 2026
```

### 3.3 坐标字段

优先使用：

- `GeometryLatitude` -> `latitude`
- `GeometryLongitude` -> `longitude`

若几何字段为空，再使用 `LATITUDE` / `LONGITUDE`。

香港坐标粗略有效范围：

```text
latitude: 22.10 - 22.60
longitude: 113.80 - 114.45
```

超出范围：

- `has_valid_coordinate=false`
- 添加 `invalid_coordinate` 标记
- 记录仍参与非地图统计

## 4. 楼龄与楼龄分组

### 4.1 楼龄公式

```text
building_age = analysis_year - occupation_permit_year
```

如果 OP 日期为空，则 `building_age=null`。

### 4.2 楼龄分组

执行版统一使用以下分组，方便与 MBIS 30 年门槛对齐：

| age_band | 条件 |
| --- | --- |
| 0-19 | 0 <= age <= 19 |
| 20-29 | 20 <= age <= 29 |
| 30-39 | 30 <= age <= 39 |
| 40-49 | 40 <= age <= 49 |
| 50-59 | 50 <= age <= 59 |
| 60+ | age >= 60 |
| Unknown | 无法计算 |

## 6. 个体风险评分

### 6.1 楼龄基础分

| 条件 | age_risk_score |
| --- | --- |
| Unknown | null |
| 0-19 | 10 |
| 20-29 | 25 |
| 30-39 | 45 |
| 40-49 | 60 |
| 50-59 | 75 |
| 60+ | 85 |

### 6.2 用途加分

| usage_group | usage_score |
| --- | --- |
| Residential/Composite | 8 |
| Office/Commercial | 10 |
| Industrial | 15 |
| Others | 5 |
| Unknown | 0 |

### 6.3 类型加分

| type_group | type_score |
| --- | --- |
| Tower | 5 |
| Podium | 3 |
| Unknown | 0 |

### 6.4 监管信号加分

| 条件 | regulatory_signal_score |
| --- | --- |
| 匹配 MBIS issued notice, High confidence | 15 |
| 匹配 MBIS issued notice, Medium confidence | 8 |
| 匹配 MWIS issued notice, High confidence | 8 |
| 无匹配或未接入 | 0 |

### 6.5 总分

Phase 1：

```text
risk_score = age_risk_score + usage_score + type_score
```

Phase 2：

```text
risk_score = age_risk_score + usage_score + type_score + regulatory_signal_score
```

约束：

```text
risk_score = min(max(risk_score, 0), 100)
```

若 `age_risk_score` 为空，则 `risk_score=null`，`risk_level=Unknown`。

### 6.6 风险等级

| risk_score | risk_level |
| --- | --- |
| null | Unknown |
| 0-30 | Low |
| 31-55 | Medium |
| 56-75 | High |
| 76-100 | Critical |

## 7. 区域指标

区域指标以 `district_en` 聚合。

### 7.1 基础指标

```text
total_buildings = count(all records)
valid_age_count = count(records where building_age is not null)
mean_age = mean(building_age)
median_age = median(building_age)
p75_age = percentile(building_age, 75)
```

### 7.2 楼龄占比

```text
share_30_plus = count(building_age >= 30) / valid_age_count
share_40_plus = count(building_age >= 40) / valid_age_count
share_50_plus = count(building_age >= 50) / valid_age_count
share_60_plus = count(building_age >= 60) / valid_age_count
```

占比输出为 0-1 小数，前端展示时转为百分比。

### 7.3 风险占比

```text
high_critical_count = count(risk_level in ["High", "Critical"])
high_critical_share = high_critical_count / count(risk_level != "Unknown")
```

### 7.4 MBIS 通知密度

```text
mbis_notice_rate = mbis_notice_count / total_buildings * 1000
```

单位：每 1000 条建筑记录的 MBIS 通知匹配数。

## 8. 区域优先级指数

Phase 1 使用 age-only index：

```text
district_priority_index =
  0.35 * normalized_median_age
  + 0.30 * normalized_share_50_plus
  + 0.25 * normalized_high_critical_share
  + 0.10 * normalized_industrial_or_commercial_share
```

Phase 2 使用 combined index：

```text
district_priority_index =
  0.30 * normalized_median_age
  + 0.25 * normalized_share_50_plus
  + 0.20 * normalized_high_critical_share
  + 0.15 * normalized_mbis_notice_rate
  + 0.10 * normalized_industrial_or_commercial_share
```

标准化方法：

```text
normalized_x = (x - min(x)) / (max(x) - min(x)) * 100
```

如果 `max(x) == min(x)`，该指标标准化为 0，避免除零。

## 9. 数据质量指标

### 9.1 个体级 flags

可用 flags：

- `missing_address`
- `missing_district`
- `missing_op_date`
- `invalid_op_date`
- `future_op_date`
- `missing_coordinate`
- `invalid_coordinate`
- `unknown_usage`
- `unknown_type`

### 9.2 数据质量分

区域级 `data_quality_score`：

```text
data_quality_score =
  100
  - missing_age_rate * 40
  - invalid_coordinate_rate * 25
  - unknown_usage_rate * 20
  - unknown_type_rate * 10
  - missing_address_rate * 5
```

结果限制在 0 到 100。

## 10. 报告指标输出 JSON

AI 和报告模块统一使用以下结构：

```json
{
  "analysis_scope": {},
  "data_version": {},
  "model_version": {},
  "portfolio_metrics": {},
  "age_distribution": [],
  "risk_distribution": [],
  "district_ranking": [],
  "usage_analysis": [],
  "regulatory_signals": {},
  "data_quality": {},
  "limitations": []
}
```

禁止报告模块重新定义指标口径。
