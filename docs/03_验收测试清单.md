# 验收测试清单

本文档用于每个阶段完成后的人工验收和自动化测试设计。

## 1. Phase 0 数据底座验收

### 1.1 命令验收

依次运行：

```bash
python -m src.data_sources.fetch_bdbiar --force
python -m src.pipeline.normalize_buildings
python -m src.pipeline.build_risk_scores
python -m src.pipeline.build_district_metrics
python -m src.pipeline.validate_outputs
```

通过标准：

- 所有命令退出码为 0。
- `data/processed/buildings.parquet` 存在。
- `data/processed/district_metrics.parquet` 存在。
- `data/cache/source_manifest.json` 存在。

### 1.2 数据验收

检查项：

| 检查项 | 通过标准 |
| --- | --- |
| 建筑记录数 | 大于 0 |
| 楼龄解析率 | 大于等于 90% |
| 坐标有效率 | 大于等于 80% |
| district 数量 | 18 个或明确说明缺失原因 |
| risk_score 范围 | 0-100 或 null |
| risk_level 值域 | Low / Medium / High / Critical / Unknown |
| data_quality_flags | 异常记录必须有 flags |

### 1.3 抽样验收

随机抽查 30 条 `buildings.parquet`：

- 地址是否保留。
- district 是否合理。
- OP 日期是否可读。
- building_age 是否等于 analysis_year - OP year。
- 坐标是否落在香港大致范围。
- risk_reason 是否能解释分数。

## 2. Phase 1 Dashboard 验收

### 2.1 启动验收

运行：

```bash
streamlit run app.py
```

通过标准：

- 页面可以打开。
- 无 Python traceback。
- 无数据时显示可理解提示。
- 有数据时显示记录数和数据版本。

### 2.2 Data Intake 页面

检查项：

- 显示当前数据源。
- 显示数据下载或生成时间。
- 显示原始记录数和有效记录数。
- 显示缺失 OP 日期、无效坐标、Unknown usage 等质量指标。
- 可看到 manifest 信息。

### 2.3 Portfolio Overview 页面

检查项：

- Total Buildings。
- Median Age。
- 30+ share。
- 50+ share。
- High/Critical share。
- 楼龄分布图。
- 风险分布图。
- 用途分布图。
- Top ageing districts。

筛选测试：

1. 选择 `Yau Tsim Mong`。
2. 再选择 `Residential/Composite`。
3. 再选择 `50-59` 或 `60+`。
4. 指标和图表必须同步更新。

### 2.4 Spatial Dashboard 页面

检查项：

- 地图默认定位香港。
- 点位颜色对应风险等级。
- tooltip 包含地址、区域、用途、楼龄、风险等级。
- 筛选后点位同步变化。
- 无坐标记录不导致页面崩溃。

大数据量检查：

- 若点位过多，页面应启用 clustering、筛选显示或 choropleth 默认视图。

### 2.5 District Benchmark 页面

检查项：

- 排名表包含 18 区。
- 可按 median_age 排序。
- 可按 share_50_plus 排序。
- 可按 district_priority_index 排序。
- 点击或选择某区后显示详情。

## 4. AI 和报告验收

### 4.1 无 API Key

操作：

- 不设置 `OPENAI_API_KEY`。
- 打开 AI Report Studio。
- 点击生成摘要。

通过标准：

- 系统生成模板摘要。
- 页面说明当前使用模板摘要。
- 不报错。

### 4.2 有 API Key

操作：

- 设置 `OPENAI_API_KEY`。
- 生成 AI 摘要。

通过标准：

- 摘要结构包含总体风险、关键发现、维护优先级、数据局限。
- 摘要不声称做过现场检测。
- 摘要不编造输入 JSON 中没有的数字。

### 4.3 报告导出

检查项：

- Markdown 报告可导出。
- HTML 报告可导出。
- 报告包含数据版本。
- 报告包含风险模型版本。
- 报告包含 prompt 版本。
- 报告包含筛选条件。
- 报告包含方法限制。

## 6. 发布前总验收

v1.0 发布或阶段交付前，按顺序检查：

1. 删除 processed 数据后重新运行 `build_all`。
2. 运行全部测试。
3. 启动 dashboard。
4. 完成一次全港分析。
5. 完成一次单区分析。
6. 完成一次高风险筛选分析。
7. 生成一份模板摘要报告。
8. 如有 API Key，生成一份 LLM 摘要报告。
9. 检查报告是否包含数据源、模型版本和限制说明。
10. 保存截图或演示记录。

全部通过后，才认为当前阶段可以进入下一阶段。Phase 0-3 全部通过后，才认为 v1.0 成品可以交付。
